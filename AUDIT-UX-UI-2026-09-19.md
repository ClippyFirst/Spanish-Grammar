# UX/UI Audit — Gramaticarrona ES

**Дата:** 2026-09-19  
**Мета:** зробити довідник не просто функціональним, а стабільним, читабельним і передбачуваним на desktop та mobile.

## Виявлені проблеми

### 1. Таблиці
- частина таблиць мала лише горизонтальний scroll для кастомних компонентів, але не для звичайних Markdown-таблиць;
- ширина колонок залежала від довжини контенту;
- на вузьких екранах текст стискався;
- контраст header/cell не був достатньо явно заданий для обох тем;
- відсутня стабільна візуальна ієрархія рядка заголовка та row-header.

### 2. Formula tokens
У CSS використовувалися `--color-token-*` змінні, але вони не були централізовано визначені в design tokens. Це створювало ризик прозорого/непередбачуваного фону й проблем із контрастом.

### 3. Mobile navigation
Desktop мав sticky TOC, але на mobile TOC повністю приховувався. Для довгих граматичних сторінок це означало втрату швидкої навігації.

### 4. Responsive overflow
Довгі формули, code/pre-блоки та таблиці могли створювати горизонтальний overflow сторінки.

### 5. Mobile header density
Елемент «Мова: українська» разом із брендом та hamburger menu міг створювати зайву щільність у вузькому header.

## Виконані зміни

- централізовано додано світлі й темні token-backgrounds;
- таблиці зроблено передбачуваними: fixed layout, стабільна ширина першої колонки, рівномірний розподіл інших колонок;
- додано zebra-row та hover без залежності від кольору як єдиного сигналу;
- додано responsive overflow для Markdown-таблиць;
- збережено горизонтальний scroll для широких conjugation/comparison tables;
- додано явні кольори тексту та фонів для таблиць;
- додано mobile TOC через доступний `details/summary`;
- на малих екранах приховано другорядний language chip;
- захищено сторінку від overflow через довгі формули/code blocks;
- покращено видимість selection/focus/interactive states.

## UX-принципи для подальшого розвитку

1. **Читабельність важливіша за щільність.**
2. **Таблиця не повинна ламати layout заради вміщення всіх колонок.**
3. **Mobile не є урізаним desktop:** довгі сторінки потребують навігації.
4. **Колір не повинен бути єдиним носієм граматичного значення.**
5. **Кожен компонент має працювати у light/dark theme.**
6. **Великі довідкові сторінки повинні мати передбачувану вертикальну ритміку.**
7. **Не додавати декоративні елементи, якщо вони не допомагають пошуку, розумінню або навігації.**

## Наступна фаза

Після локального `npm run build:full` потрібен візуальний QA щонайменше для:

- головної;
- сторінки категорії;
- короткої граматичної сторінки;
- дуже довгої C1–C2 сторінки;
- сторінки з 8–10+ колонками таблиці;
- сторінки з Formula/Token/Mistake/Example;
- mobile widths приблизно 320, 375, 768 px;
- desktop приблизно 1280–1440 px;
- light + dark system theme.

Особливо перевірити: горизонтальний overflow, контраст, довгі слова/формули, sticky header + anchor scrolling, таблиці, TOC і Pagefind.
