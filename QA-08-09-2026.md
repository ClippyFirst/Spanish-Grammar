# Q&A — Стан розробки проєкту GrammarWay ES (08.09.2026)

Цей документ містить відповіді на найпоширеніші питання про поточний стан розробки, архітектуру, контент та запуск проєкту **GrammarWay ES**.

---

### ❓ 1. Що це за проєкт та яка його головна мета?
**GrammarWay ES** — це статичний довідник з іспанської граматики, створений спеціально для україномовних користувачів.
* **Головний принцип**: «Знайти → зрозуміти → порівняти → запам'ятати».
* **Основний підхід**: Пояснення подаються українською мовою з наочними прикладами, контрастним порівнянням форм, розбором типових помилок та безпосереднім зіставленням іспанської граматики з українською/англійською.

---

### ❓ 2. Це платформа чи звичайний веб-сайт?
* **З технічного боку**: Це **надшвидкий статичний веб-сайт** (JAMstack). Він не потребує бази даних, сервера або авторизації. Усі сторінки компілюються в чистий HTML/CSS/JS під час збірки.
* **За концепцією**: Це **навчальна граматична платформа**. Вона використовує строкову модель даних (Astro Content Collections зі Zod-схемами), систему інтерактивних MDX-компонентів, клієнтський повнотекстовий пошук (Pagefind) та архітектуру, готова до розширення іншими мовами (`/fr/`, `/it/`).

---

### ❓ 3. Який стек технологій використовується?
* **Фреймворк**: [Astro 5](https://astro.build/) + [TypeScript](https://www.typescriptlang.org/)
* **Формат контенту**: [MDX](https://mdxjs.com/) (Markdown + Astro Components)
* **Пошук**: [Pagefind](https://pagefind.app/) (клієнтський індекс без бекенду)
* **Стилі**: Модульний CSS з системою токенів (кольори, типографіка, сітка).

---

### ❓ 4. Які UI-компоненти реалізовані для подачі граматики?
Усі статті розробляються в MDX з використанням спеціалізованих компонентів з `src/components/`:
* `<Formula>` — візуальні формули побудови граматичних конструкцій та часів.
* `<Conjugation>` — таблиці відмінювання дієслів.
* `<Example>` — приклади речень з колірним акцентом та україномовним перекладом.
* `<Mistake>` — блоковий аналіз типових помилок (*«Правильно / Неправильно»* + пояснення *«Чому?»*).
* `<MinPair>` — мінімальні пари для аналізу різниці у значеннях.
* `<Note>` — кольорові картки з важливими примітками та нюансами.
* `<Token>` — морфологічне підсвічування частин мови та закріплення правил.
* `<CompareTable>` — зведені таблиці складних протиставлень.

---

### ❓ 5. Яка структура розділів та який контент вже готовий?
У проєкті закладено **16 граматичних категорій** (`data/categories.ts`). Наразі підготовлено каркас та базовий пул MDX-матеріалів:
* **Основні теми**:
  * *Fundamentals*: Алфавіт та вимова (`alphabet-pronunciation`)
  * *Nouns*: Рід іменників (`genero`)
  * *Articles*: Визначені та невизначені артиклі (`definite-indefinite`)
  * *Adjectives*: Узгодження прикметників (`adjective-agreement`)
  * *Verbs / Tenses*: `ser` vs `estar`, `gustar`, `presente-de-indicativo`, `preterito-indefinido`, `preterito-imperfecto`, `preterito-perfecto`.
  * *Moods*: `subjuntivo-presente`
  * *Pronouns & Prepositions*: `objeto-directo-indirecto`, `personal-a`, `por-para`.
  * *Periphrases & Regional*: `estar-gerundio`, `voseo`, `regional-overview`.
  * *Sentence Structure*: `negation`.
* **Розділ порівнянь (`/comparisons/`)**: Готові матеріали з контрастного аналізу (`por` vs `para`, `ser` vs `estar`, минулі часи, артиклі, індикатив vs суб'юнктив).

---

### ❓ 6. Як працює система пошуку?
Пошук реалізовано через **Pagefind**.
При виконанні команди `npm run build:full` Pagefind сканує згенеровані HTML-файли в папці `dist/` і будує компактний статичний індекс. При відвідуванні сторінки `/search` індекс завантажується у браузер і миттєво знаходить теми за українськими, іспанськими чи англійськими ключовими словами.

---

### ❓ 7. Як запустити проєкт локально?

1. **Встановлення залежностей**:
   ```bash
   npm install
   ```

2. **Запуск сервера розробки (Dev mode)**:
   ```bash
   npm run dev
   ```
   *Сайт буде доступний за адресою `http://localhost:4321`.*

3. **Повна збірка сайту та індексу пошуку**:
   ```bash
   npm run build:full
   ```

4. **Локальний перегляд згенерованого сайту (з робочим пошуком)**:
   ```bash
   npm run preview
   ```

5. **Перевірка типів та схем контенту**:
   ```bash
   npm run check
   ```

---

### ❓ 8. Які наступні кроки у розробці?
1. Заповнення решти MDX-статей для всіх 16 категорій граматики.
2. Автоматична перевірка внутрішніх посилань (`related`) та валідація frontmatter.
3. Налаштування CI/CD для автоматичного деплою сайту на GitHub Pages чи Cloudflare Pages (`npm run build:full`).
