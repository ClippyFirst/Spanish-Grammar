# Матриця аудиту навичок Gramaticarrona

**Дата інвентаризації:** 2026-10-18  
**Гілка набору навичок:** `feat/grammar-research-skills-2026-10-18`  
**Статус:** source-level інвентаризація специфікацій; не означає, що навички пройшли емпіричне тестування або що повний `npm run qa` успішний.

## 1. Критерії оцінювання

Цей проєкт — граматичний довідник, не повний курс чи LMS. Можна пропонувати **необов'язкові добірки та шляхи переходу між темами**, але читач має мати змогу знайти відповідь без проходження маршруту. Не вимагати вправ, балів, зворотного зв'язку до відповідей або spaced repetition як умов якості статті.

Кожна навичка оцінюється за:
- відповідністю реальній задачі довідника;
- унікальністю відповідальності та перетином з іншими навичками;
- вимогами до джерел і відтворюваності доказів;
- здатністю відрізнити «відсутнє», «наявне, але не перевірене» і «перевірене»;
- перевіркою на позитивному, негативному й неоднозначному прикладі;
- зрозумілим результатом, який можна використати для виправлення;
- відсутністю непідтверджених висновків про нормативність, частотність, регіон або помилки читачів.

## 2. Інвентаризація навичок

Позначення:
- **Основна** — регулярна частина відповідного аудиту.
- **Умовна** — запускати лише коли конкретна сторінка/зміна потребує цієї спеціалізації.
- **Перепрофілювати** — ідея корисна, але опис треба узгодити з форматом довідника.
- **Обмежити** — не використовувати як типовий етап; зберігати для вузького сценарію.
- **Перетин** — потенційне дублювання, яке треба розмежувати в маршрутизації.

## 3. Пріоритетний маршрут аудиту статті

1. **Інвентаризація й контекст:** canonical topic, пов'язані сторінки, статус покриття та відомі findings.
2. **Граматична точність:** `spanish-grammar-fact-checker`; додати `spanish-variation-auditor`, якщо є варіантність.
3. **Приклади:** `spanish-example-corpus-auditor`; `spanish-example-naturalness-auditor` для прикладів, де природність/контекст неочевидні; morphology/orthography за типом матеріалу.
4. **Українське пояснення:** `spanish-ukrainian-contrastive` для зіставлень; `ukrainian-spanish-proofread` і `spanish-terminology-auditor` для редактури.
5. **Джерела:** `citation-integrity-auditor` на точних твердженнях; `spanish-corpus-evidence-auditor` лише для частотності/вживання.
6. **Узгодженість корпусу:** `grammar-coverage-auditor` і `grammar-knowledge-graph-auditor` періодично або після структурних змін.
7. **Візуальне рішення:** `grammar-visualization-auditor` лише якщо є конкретна проблема, яку графіка може краще пояснити.
8. **Редакційний фініш:** `academic-proofreading`, потім відповідні технічні скрипти та `npm run qa`.
9. **Реліз:** ручний браузерний/доступнісний аудит і технічний SEO-аудит за наявності середовища.

Не запускайте всі 29 навичок на кожній сторінці. Обирайте найкоротший маршрут, що відповідає ризику й типу зміни.

## 4. Позитивні, негативні та неоднозначні перевірки

| Навичка/група | Позитивний випадок | Негативний випадок | Неоднозначний випадок |
|---|---|---|---|
| Fact-check + citation integrity | Категоричне правило має перевірюване джерело й межі | Твердження без джерела | Джерело описує інший регіон або інший контекст |
| Variation + pragmatics | Позначений регіональний/розмовний контраст | Варіант оголошено помилкою без доказу | Регіональна перевага змінюється залежно від жанру |
| Contrastive + Ukrainian proofread | Функціональна аналогія без хибної еквівалентності | Дослівна калька подається як правило | Український переклад приховує іспанську неоднозначність |
| Example auditors | Приклад із достатнім контекстом і підтвердженим походженням | Вигадане твердження про корпусну частотність | Приклад граматичний, але прагматично дивний без контексту |
| Coverage + graph | Відсутня тема зі стабільним canonical slug | Збіг назви помилково вважається достатнім покриттям | Підтема може бути окремою сторінкою або підрозділом |
| Learning/reference design | Необов'язкова добірка логічно веде від передумови до нюансу | Обов'язковий курс/прогрес-трекер пропонується для довідника | Чи потрібна схема, таблиця або лише контрастний приклад |
| Visualization | Часовий/структурний зв'язок справді важко зрозуміти з тексту | Декоративна схема для простого правила | Візуал може приховати контекстну або регіональну варіативність |
| Accessibility/browser | Є реальний тест viewport/клавіатури/таблиці | «Доступно» оголошено лише за переглядом вихідного коду | Автоматичний тест проходить, але реальний фокус/читач не перевірений |
| SEO | Пошуковий намір отримує чітку й корисну відповідь | Текст роздуто ключовими словами | Дублювання між канонічною статтею та порівнянням |

## 5. Перші пілотні сторінки

Використати три різні типи матеріалу:
- **`ser/estar`** — семантичний контраст, мнемонічні спрощення, регіональна/контекстна межа, синхронізація канонічної та порівняльної статті.
- **`pretérito indefinido / imperfecto`** — часо-видовий контраст, приклади, передумови та можливість/недоречність часової шкали.
- **позиція клітик / `se`** — морфосинтаксис, структурна схема за потреби, регіональні нюанси та міжсторінкова узгодженість.

Для кожної пілотної сторінки фіксувати: конкретні файли/рядки, знахідку, доказ, упевненість, false positive/false negative, рекомендовану правку й регресійний тест. Поки немає виконаного тесту, результат має статус **source-level / не перевірено локальним QA**.

## 6. Що не можна стверджувати на цьому етапі

- Що всі навички перевірені на практиці або валідовані.
- Що весь корпус граматично вичерпний.
- Що зовнішні джерела/корпуси були фактично запитані, якщо немає журналу запиту.
- Що браузер, адаптивність або доступність пройшли тест, якщо запуск не відбувся.
- Що відсутня тема, якщо вона не була перевірена в повному корпусі.
- Що певна помилка типова для українськомовних без досліджень або чіткої позначки гіпотези.

## 7. Наступні дії

1. Перепрофілювати `learning-design` і `education-content` під довідник та необов'язкові тематичні шляхи.
2. Залишити `grammar-exercise-validator` умовною навичкою, не частиною стандартного аудиту.
3. Внести чітке розмежування між `spanish-forms-auditor` і `spanish-morphology-paradigm-auditor`.
4. Додати `grammar-visualization-auditor` і включити його в індекс.
5. Пройти три пілотні статті; після цього змінювати матрицю за реальними результатами, а не припущеннями.
6. Запустити `npm run qa` у локальному checkout/CI та зафіксувати фактичний результат перед злиттям.
