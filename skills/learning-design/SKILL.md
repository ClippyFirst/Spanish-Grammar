# Learning Design

## Goal
Help the reference support durable understanding, not merely exposure to definitions.

## Procedure
1. State the likely learner task in observable terms: distinguish forms, interpret a construction, produce a form, or correct a misconception.
2. Check prerequisites and links to prerequisite topics.
3. Build a progression: recognition → guided contrast → constrained production → contextual application, only where suitable.
4. Check whether examples isolate the target distinction or contain distracting unknown structures.
5. Recommend retrieval questions and minimal pairs that require the learner to retrieve the rule rather than reread it.
6. Include feedback explaining why an answer works and why plausible alternatives fail.
7. Vary contexts without changing the target construct; avoid repetitive drills that reward pattern guessing.
8. Recommend spaced review only when a real practice flow exists; do not imply the static site currently implements scheduling.
9. Define a testable success criterion for any proposed exercise.

## Output
Learning objective; assumed prerequisites; sequence; proposed task(s); answer key and rationale; likely ambiguity; evidence needed to validate effectiveness.

## Guardrails
Do not invent empirical learning gains or call a page CEFR-aligned without an explicit mapping. Distinguish design hypotheses from tested outcomes. Do not force exercises onto reference pages whose purpose is quick lookup. Use the project's existing `prerequisites`, `contrasts`, `extensions` and `exceptions` fields where appropriate.
